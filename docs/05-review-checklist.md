# V0.1 评审与实施安排

> 状态：历史候选设计（保留原方案与评审语境）。本文不作为当前功能规格或验收要求；当前实现见 [资源入库闭环](12-resource-ingestion.md)，开发与验证见 [开发工作流](development-workflow.md)。下文的“当前”“本轮”均指历史编写阶段。

## 评审内容

- [ ] 一个 Spring Boot 应用能够覆盖当前场景管理与内容发布需求。
- [ ] 白天、夜晚分别发布和回滚，互不覆盖。
- [ ] 内容冻结后不可修改，文件验证通过后才能发布。
- [ ] 发布与回滚通过一次事务切换指针，并记录操作人。
- [ ] 游客只能取得曾发布且仍有效的版本。
- [ ] 所有管理员具有相同权限，每次修改均可追溯到账号。

## 成品交付格式确认

保留“场景—内容版本—成品文件”的分离，先取得一个能被目标客户端加载的真实成品，再确定文件管理粒度。对接时确认：

- 交付物是每平台一个完整包，还是入口文件加多个依赖文件？
- 客户端如何加载入口、寻找依赖、使用签名下载链接？
- 一次内容更新需要整体替换，还是确有独立文件更新或复用需求？
- 各平台的格式、典型大小和最大包体是多少？

确认结果需附样例目录、加载说明和包体数据，再同步调整 SQL、接口、流程及关系图。当前多文件关联结构仅用于候选方案验证。

## 后续实施顺序

1. 创建应用工程，接入数据库脚本、登录、Session 和 CSRF。
2. 实现场景与标记；确认成品格式并修订文件契约后，实现文件直传与校验。
3. 实现版本草稿、文件关联和冻结。
4. 实现预览、发布、回滚和扫码清单。
5. 完成运行配置、备份恢复及真实设备验收后部署。

评审数据库时可结合外键、索引、短事务和乐观锁学习；评审上传流程时重点理解文件摘要、不可覆盖的对象键和重复请求处理。数据库任务队列不属于 V0.1 的学习前置条件。

## 验收要求

数据库检查覆盖数据一致性。HTTP 登录、实际对象存储读写、客户端渲染和定位需要分别验证。

设备验收记录机型、系统、网络、光照、资源包大小、识别时间与恢复时间。接口成功仅表示服务返回正常，定位体验仍需现场确认。

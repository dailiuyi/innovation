## 目标与验收

在现有“内容版本草稿”页面支持选择文件夹、递归上传其中的文件，并提供两条下载流程：ZIP 整包下载，以及获取完整清单后逐文件下载、还原原始目录。

页面是简单的操作与接口测试入口，不建设完整网盘。真实客户端格式尚未确定，本次不固定 Unity Addressables、AssetBundle 或 AR 加载协议。

### 用户已确认的需求

1. 两种下载都做：ZIP 整包，以及完整文件清单加单文件下载接口。
2. 这次仅面向已登录管理员。管理端可下载草稿或已发布版本，为未来客户端保留可复用能力；客户端访问与认证后续确定。
3. 前端提供 ZIP 下载、查看完整清单和单文件下载入口。用测试脚本验证按清单下载并还原整个目录；不要求网页直接写入本机文件夹。
4. 不需要移动、重命名、分享或预览等复杂网盘功能。
5. 单文件和 ZIP 下载接口均支持断点续传。ZIP 可以先准备完成再下载，接受首次准备时间。
6. 预计为小型资源目录：通常不超过 200 个文件，总量不超过 500 MiB。这是用户对预计规模的选择，不是已经确认的永久硬限制。
7. 选择文件夹上传时，如果当前草稿已有文件，必须提示此次操作会替换当前草稿的全部文件，并取得确认。不能仅追加新目录而留下旧文件。
8. 新文件全部上传、校验成功后才切换；之前保留旧文件。失败可以重试或取消，替换期间禁止发布和下载。取消替换后恢复原集合使用。
9. 保留所选顶层文件夹。例如选择“场景A”，保存和交付的相对路径为 `场景A/models/a.bundle`。
10. 修正现有发布规则：有失败文件的草稿不允许发布。必须整份草稿全部文件完整且校验通过，才能发布或下载；不能静默跳过失败文件生成不完整下载结果。

### 范围与明确不做

- 继续使用一个 Spring Boot 实例、内网私有本地 ArtifactStorage，以及当前管理员账号体系。
- 不增加任务队列、Worker、对象存储、CDN、匿名分享或客户端认证体系。
- 不实现 AR 加载、资源预览、目录整理或客户端兼容性判断。
- 不自动提交、合并、部署或重启日常 Demo。此次交接文档不代表这些操作已获授权。

## 建议实现方案

以下是讨论中形成的技术建议和默认值。Grok 应结合当前实现落地；涉及改变上方用户确认项时，先重新讨论，不自行缩减需求。

### 1. 相对路径与上传批次

- 为文件增加独立相对路径字段，保留原文件名。数据库表达目录，实际内容继续使用服务端生成的 UUID 存储，不把用户路径直接用于服务器落盘。
- 引入持久化“文件集合／替换批次”及当前集合指针。先登记本次完整文件清单，再上传内容；不能只知道已经开始上传的文件，而不知道遗漏了哪些文件。
- 待替换集合和当前集合分开。上传期间保留旧集合，新集合全部校验成功后在数据库事务内切换当前集合。文件 I/O 不放入长数据库事务。
- 同一草稿只允许一个待完成替换批次。替换期间禁止发布、下载和其他文件增删；允许查询进度、重试与取消。
- 重选相同目录应按批次、相对路径、大小和摘要识别已完成文件及重试文件；同批次的清单或内容变化不得悄悄拼成另一套目录。
- 取消时清理新集合；切换成功后清理旧集合。用持久化状态、已有删除意图和启动恢复处理崩溃，不以浏览器状态作为唯一进度依据。
- 路径检查覆盖绝对路径、越界片段、控制字符、规范化冲突、文件与目录前缀冲突，以及目标环境不能安全还原的名称。
- 建议首版不保留空目录；限制默认每集合 200 个文件、500 MiB，做成配置项；单文件上限沿用当前配置（本机默认 256 MiB）。这些属于建议默认值。
- 旧文件需要迁移为当前集合并补充导出路径；旧记录同名或名称不合法时，采用确定性的安全路径，保留原文件名，不覆盖实际内容。
- 当前普通文件上传入口建议保留追加含义，文件夹入口明确标注“替换全部文件”。这是尚未单独确认的兼容建议；若保留，需遵守集合唯一路径、下载失效和并发保护规则，不能绕过文件夹替换限制。
- 保留现有 RESOURCE_FILE / CLIENT_LIBRARY 及 AAR 限制；打 ZIP 不改变文件业务类型。

### 2. 完整性与两条下载流程

所有下载入口及发布共用完整性检查：草稿非空、无未完成替换／上传／删除，全部当前文件可用，实际存储大小和 SHA256 校验通过。单文件下载也不绕过用户要求的整份完整性门槛。

建议接口均位于 `/api/v1/drafts/{draftId}` 下，并沿用管理员 Bearer 鉴权：

| 方法与子路径 | 用途 |
|---|---|
| `GET /download-manifest` | 返回集合标识、全部文件的相对路径、大小、SHA256 和单文件下载地址 |
| `GET/HEAD /files/{fileId}/content` | 下载或查询单文件；同路径现有 PUT 上传保持原用途 |
| `POST /zip-exports` | 携带集合标识，准备或复用 ZIP，返回下载地址、大小、SHA256 |
| `GET/HEAD /zip-exports/{exportId}/content` | 下载已经完整生成的 ZIP |

- 清单代表完整集合，不能误用现有分页文件表的第一页。清单与下载请求绑定集合标识；集合变化后旧请求明确失败，不能返回新旧混合内容。
- ZIP 保存清单中的相对路径，不额外插入未经约定的业务文件。先生成临时文件，完成并校验后原子提交；失败文件不能作为成功下载提供。
- 按需生成 ZIP，不把 ZIP 生成变成发布前置任务；同一集合可复用已准备好的 ZIP。
- 单文件和 ZIP 支持强 ETag、Range、If-Range，以及正确的 200/206/416、Content-Length、Content-Range、下载文件名。ETag 对应实际响应内容，避免续传时拼接不同文件。
- 变更、删除文件或草稿时使关联清单／ZIP 失效并清理缓存；旧 ZIP 地址不能悄悄指向新包。建议缓存保留 24 小时、总量上限 2 GiB，均可配置；缓存过期后调用方重新准备下载。
- 下载、校验和打包与写操作建立一致的读取保护；冲突修改返回可重试提示。保护范围覆盖流传输期间及所有旧的写入口，不只保护创建清单时的瞬间。
- ZIP 缓存、取消批次和退休集合的清理不能删除正在读取的内容；进程中断后能够恢复清理。实现需处理存储空间不足、打包失败和请求中断。

### 3. 简单页面与测试工具

- 增加“选择文件夹并上传”，显示相对路径、文件总数、总大小、整体进度、失败项及取消替换入口。
- 替换确认说明：新目录完整上传并校验成功后永久替换原文件；上传失败可重试或取消。取消确认框不发起替换。
- 增加“下载 ZIP”“查看下载清单”和文件行“下载”；不满足完整性条件时展示具体原因。ZIP 首次准备阶段明确显示状态。
- 下载请求带现有登录身份，不把令牌放进 URL；下载二进制时正确处理鉴权失败和 JSON 错误，不保存成假 ZIP。
- 本次不做跨页面恢复的浏览器下载管理器。断点续传能力通过真实接口与脚本验证；页面提供正常下载和错误提示。
- 扩展现有参考下载工具或增加独立测试入口：读取清单、校验安全路径、逐文件下载、恢复顶层文件夹并验证全部摘要。通过环境变量或交互读取认证信息，不把凭据写入文档或日志。
